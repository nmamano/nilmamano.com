I've spent the last few months building [isomux](https://isomux.com), a meta-harness that runs Claude Code and Codex side by side, and I wrote about [how it works](/blog/isomux). This post is the other half: what the interface should actually do.

Let's talk about ways of making agents more user-friendly!

## Prettify curl tool calls

Detect via regex when an agent curls your own system and prettify the tool call.

<BlogImage
  src="/blog/isomux/curl-cards.png"
  alt="A stack of tool-call rows in the chat, each a curl call to the isomux API rendered as a labeled card: 'Create task' with title, description, and priority chips; 'Edit Isomuxer3's settings' with modelFamily and effort chips; 'Clear Isomuxer3's conversation'; 'Claim task a65621b0 for Isomuxer3'; and 'Send a message to Isomuxer3' with a text chip"
  caption="Same tool calls, minus the shell."
/>

Bonus: each tool call should be a single line, unless it errored out. Otherwise they bury useful content.

## The context meter as a battery

Remaining context is like your phone's battery. When it starts to run low, you need to start looking for a good stopping point and recharge.

<BlogImage
  src="/posts/another-ui-polish-in-isomux-see-how-much-5074318/context-meter.png"
  alt="The isomux conversation header showing the model name 'Opus 4.8' next to a nearly empty battery icon and '24%', with a red arrow pointing at the meter"
  width="70%"
  caption="24% left, and it looks like 24% left."
/>

In addition, when remaining context drops below 50% and 75%, I let the agent know, so they can start prompting the user toward a good stopping point.

The recharge is a `/handoff` command: the agent writes a brief of what's left, I approve it, and it restarts from just that.

## Don't make users remember skill names

Give them a UI to find their [skills](/posts/isomux-qol-feature-a-skills-button-7484769), sorted by what they use most.

<BlogImage

I like to show the counts :)

## Don't let agents yap. Make them design a slide

A slide can't hold a wall of text, so the model has to decide what actually matters.

[Slide mode](/posts/another-weekend-sidequest-slidegpt-4492825) takes the agent's last turn and turns it into a slide.

<BlogImage
  src="/posts/another-weekend-sidequest-slidegpt-4492825/deck-decisions.png"

  caption="One turn, one slide. The arrows walk back through the conversation."
/>

## Anthropomorphize agents

We're used to working with _people_, so make agents persistent. A name, a look, memories built over time, its own conversation history, etc.

  width="55%"
  caption="Desk 3. She's asleep because I only need her once a year."

Even better if you give them body language: let them look busy while working, [wave when they need you](/posts/now-give-each-one-a-little-avatar-4450247), and [snooze off when idle](/posts/omg-they-are-all-sleeping-now-so-0990636).

You can even show their body language in the [browser tab](/posts/browser-tabs-when-talking-to-an-agent-5049422).

## Human collaboration at the agent level

Everyone is at a different point in their AI journey. Letting the technical users [see the conversations of non-technical users](/posts/unexplored-area-in-agent-management-systems-human-1081928) and step in when they get stuck will be huge for onboarding non-technical users.

## Let agents put things in chat that aren't text

Add one REST endpoint per component, tell agents about it in the system prompt, and they stop describing things and start showing them.

  src="/blog/isomux/superpowers.png"

The chat panel shows the resulting components: an inline diff, an 'Open in editor' card, a 'Copy to terminal' card, and an inter-agent message"
/>

## Make it easy for agents to tie loose ends

Give them access to a shared [human-agent task board](/posts/task-system-designed-for-both-humans-and-9025617) where they can put follow-up tasks for later.

<BlogVideo
  src="/posts/task-system-designed-for-both-humans-and-9025617/2040871759529025617-OUFbPVfeqWAcVkCi.mp4"
  caption="Asking one agent to file a task for another, then finding it on the corkboard in the office."
/>

I recommend having a `/wrap-session` skill that tells agents to make sure there's no loose ends by filing follow-up tasks, saving memories, updating skills, git stuff, etc.

## Mixed human-agent queues

For [a well-made queue](/posts/decision-when-building-agents-queueing-vs-steering-9972381), it's all in the details:

- let agents know who sent each message (which human and/or agent)
- let agents know whether the messages arrived in response to their last message or before that
- let users queue or steer
- let users modify queued messages
- etc.

## Less magic

Add commands for seeing the [system prompt](/posts/any-agent-management-system-should-have-hierarchical-5534346), disk use, etc.

> **[image placeholder]** the storage command

Here's what happens when a tool tries to be more magic than that. Because of [an old Gemini bug](/posts/there-was-this-bug-in-gemini-where-2679064) where only some models saw the system prompt, I plant a line in my custom instructions saying "My name is Bongo, I like being addressed by my name", and then I ask the model who it's talking to. If it doesn't say Bongo, my instructions never made it in.

## The 5-hour hack

Ping each provider every 5 hours automatically. This way, the [5h window](/posts/timing-my-5h-usage-window-so-it-5085835) resets on average 2.5h after you start working.

## Voice both ways

One advantage of a browser-based frontend is that you can lean on the browser's existing speech-recognition and speech-synthesis APIs, for prompts and replies respectively. [Rambling at an agent with voice input](/posts/software-for-one-recipe-4158869) is the fastest way I know to update the state of a system, because I don't have to know the precise operations, I just have to describe them.

## Deterministic hooks for big no-no actions

Like `rm -rf`, reading environment files, etc. Never allow these, but give the agent a way to make it easy for you to do them if you still want.

## Keep the user's latest message at the top

Showing the user's latest message, sticky at the top of the chat, for context on what the agent is responding to. Clicking it navigates to it.
